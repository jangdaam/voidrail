# Voidrail — 목표에 따라 특수 공간이 연결되는 하역장

기준: jangdaam/voidrail city 브랜치, 0824756eedaf3067135d11aba8dfda39e6867899.
2026-11-17. 목표 기반 운행 디렉터 위에 양안 하역 설비와 중앙·경사 코스를 추가했습니다.

## 실행과 시험

- Node.js가 설치된 환경에서 이 폴더에서 `node serve.mjs` 실행 후 http://127.0.0.1:5178/ 접속. 서버는 로컬 인터페이스에만 열립니다.
- `?seed=1234&debug`로 열면 목표 시험 버튼이 표시됩니다. F3으로 표시/숨김을 전환합니다.
- `명세서 확보 완료`는 중앙 하역장, `전력 복구 완료`는 층간 상승 구간을 예약합니다.
- `예약 공간 입구로`는 다음 예약 구역 180m 앞까지 이동합니다. `다음 구간`으로 해당 구역에 진입할 수 있습니다. `이벤트 통과 시험`은 출구로 이동합니다. 모두 개발용 순간이동이며 실제 플레이 규칙이 아닙니다.
- `처음으로`와 `새 시드`는 목표와 이벤트 예약도 초기화합니다. 새로고침 후 운행 상태 저장/복원은 아직 없습니다.
- `npm run check`: 문법, 생성/경로, 디렉터, 로컬 전송 회귀 검사.
- `node build-preview.mjs`: 소스 수정 후 오프라인 HTML 재생성.
- `industrial-preview.html`은 Edge에서 직접 열 수 있는 단독 검토본입니다. 4인 온라인 시험에는 개발 서버/적절한 호스팅이 필요합니다.

마우스 시점, WASD 이동, Space 점프, Shift 달리기, E 레버, Z/X 감속/가속, V 외부 시점, R 안전줄 복귀, M 음소거. 외부 시점은 드래그와 휠을 사용합니다.

## 생성 규칙

일반 하역장은 창고 반입구, 적치장, 탱크, 컨베이어를 시드로 조합합니다. 완성된 방 프리팹을 순서대로 반복하는 대신 네 개의 종방향 작업 셀에서 선로 여유 폭에 따라 양쪽 베이의 유무, 간격, 폭, 높이, 깊이, 설비 종류를 결정합니다. 일반 구역에는 중앙 횡단, 상승 조망, 좌우 횡단 코스가 나오며 조건을 충족하지 않는 한 계속 이어집니다. 상승 조망 코스는 18~36m 올라갔다가 원래 높이로 돌아와 다음 구역과 연결됩니다. 시간이나 주행 거리만으로 이벤트를 발생시키지 않습니다.

선로에는 현재 1,400m 접속 단위를 유지합니다. 터널과 선로의 공통 접속 규격은 고정이고, 내부 작업장 풍경을 변화시키는 단계입니다. 무한히 새로운 선로 위상이나 갈림길을 생성하는 구현은 아닙니다.

특수 공간은 기존에 설계한 중앙 하역장과 78m 상승 구간 두 가지입니다. 중앙 하역장은 평탄하고, 상승 공간에서만 이후 구역의 기준 높이가 올라갑니다. 두 공간은 현재 같은 산업 설비 세트를 바탕으로 하며, 독립적인 사건별 미술 및 퍼즐은 앞으로 확장해야 합니다.

예약 시 열차에서 최소 2,000m 앞이며 이미 생성 또는 생성 예약된 구역 이후인 슬롯을 선택합니다. 카메라 원경 한계 1,700m 밖에서 결정하므로 눈앞의 배치나 현재 선로를 바꾸지 않습니다. 특수 공간 사이에는 최소 한 구역의 일반 풍경을 둡니다. 목표를 달성한 즉시 특수 공간이 눈앞에 나타나지는 않습니다.

이벤트 상태는 조건 대기 → 예약 → 접근 → 진행 → 통과 완료입니다. 동일한 트리거 ID는 한 번만 처리하고, 완료된 이벤트는 뒤로 이동해도 재실행하지 않습니다. 한 운행의 이벤트 기록은 최대 256개이며 일반 구간의 시간 제한은 없습니다. 현재 완료는 구역 출구 통과 기준입니다. 적 제거, 장치 수리 같은 미션 성공/실패 판정은 별도 시스템으로 연결해야 합니다.

## 게임플레이 연결 API

기관사에서 실제 조건을 검증한 후 호출합니다. 승객의 임의 목표 완료 요청은 허용하지 않습니다. 일반 클라이언트 상호작용 검증/전송은 후속 게임플레이 구현에서 추가합니다.

`window.voidrailEvents.request('ascent', 'main-lift')`
: 목표 달성 전에 상승 이벤트를 대기열에 등록. power 목표가 완료되면 예약됩니다.

`window.voidrailEvents.completeGoal('power')`
: 전력 목표 완료. 대기 요청이 없으면 상승 공간 하나를 자동 예약합니다.

`window.voidrailEvents.completeGoal('manifest')`
: 명세서 목표 완료 후 중앙 하역장을 예약합니다.

`window.voidrailEvents.trigger('cargo', 'sensor-dock-17')`
: 특정 센서/사건 등 직접 트리거. 목표를 기다리지 않고 예약하며, 같은 ID로 다시 호출해도 중복되지 않습니다.

`window.voidrailEvents.snapshot()`
: 운행 ID, 시드, 목표, 예약 슬롯, 진행 상태를 읽습니다.

다른 이벤트를 추가할 때는 run-director.js의 유형/목표 정의, track.js의 높이 및 접속 규격, city.js의 해당 공간 빌더를 함께 연결합니다.

## 동기화와 주요 소스

기관사가 목표와 예약을 결정하고 기존 열차 신뢰 채널에 운행 스냅샷을 포함합니다. 시드만 공유하면 플레이 중 선택된 이벤트 배치는 재현되지 않으므로 이벤트 유형과 구역 인덱스도 공유합니다. 초기 참가 인사에서 기존 운행 상태와 방의 기원을 전달합니다. 운행의 기원과 최저 ID의 기관사 선출을 분리하여 새 기관사가 자신의 초기 맵으로 기존 운행을 덮지 않도록 합니다. 뒤늦게 도착한 기존 방 소개도 새 참가자의 소개보다 우선합니다. 뒤늦은 상태 때문에 이미 만든 지형을 바꿔야 하면 로딩 페이드에서 재생성합니다. 같은 운행의 오래된 리비전, 중복 슬롯, 기존 이벤트를 다른 슬롯으로 옮기는 스냅샷은 거부합니다.

- js/run-director.js: DOM/렌더러에 의존하지 않는 예약·목표·상태·스냅샷 검증.
- js/run-state.js: 운행 수명과 시드 변경.
- js/ordinary-harbor.js: 일반 작업장 배치 규칙 및 재질별 병합 메시.
- js/industrial-kit.js: 드럼·롤러·모터·권상기·후크·펌프·밸브·감시 카메라와 모따기 형상.
- js/track.js: 중앙/경사/좌우 횡단 및 이벤트 상승 경로, 다음 구역의 누적 높이, 예약 변경 시 경로 캐시 갱신.
- js/city.js: 청크 고정 및 일반/특수 빌더 선택, 기존 크레인·리프트.
- js/main.js, js/ui.js: 목표 API, 디버그 조작, 기관사 권한과 동기화 연결.
- js/net/room-origin.js, js/net/session.js, js/net/transport.js: 초기 운행 전달, 퇴장 뒤 지연 패킷으로 참가자가 복구되는 문제 수정.
- js/harbor-plan.js, js/harbor.js: 기존 특수 하역장 건축과 이동 화물.

## 검증 범위

자동 검사는 4개 시드·48개 배치, 선로 접속 연속성, 기존 경로 불변성, 건물 여유 공간, 이벤트 중복/대기/완료, 잘못된 스냅샷의 원자적 거부, 늦은 참가자의 경로 재현, 로컬 전송 초기 인사와 퇴장 후 패킷 처리, 참가 인사의 순서가 바뀌어도 기존 운행을 선택하는지를 확인합니다. 조건 없이 최대 속도로 30분에 해당하는 54km를 진행하는 로직 시뮬레이션도 포함합니다. 이는 실제로 30분간 플레이하거나 재미와 성능을 검증했다는 뜻이 아닙니다.

일반 하역장 배경은 설비 디테일을 늘려 구역당 130,000개 삼각형 상한을 자동 검사합니다. 정적 배치 세 개와 움직이는 화물 인스턴스 한 개로 4회 드로콜입니다. 선로 청크, 열차, 기타 장면 전체는 제외한 수치입니다. 기존 특수 공간의 추가 건축과 화물은 2,616개 삼각형/3회 드로콜이며 기존 설비 전체 예산은 아닙니다. 안개는 거리/높이 기반 셰이더로 처리하고 실제 볼류메트릭 레이마칭이나 실시간 그림자 맵을 추가하지 않았습니다.

브라우저에서 일반 구간, 목표 예약, 특수 공간 진입/통과를 검사했습니다. 같은 브라우저의 네 탭으로 지연/손실을 흉내 낸 로컬 연결을 검사하며, 실제 원격 WebRTC 4인 플레이 및 장시간 성능은 별도 검증이 필요합니다.

이번 작업은 일반 구역의 시각 설계, 중앙·경사 경로, 공간 생성과 이벤트 배치 로직입니다. 명세서 찾기/전력 복구 미션, 하차 충돌, 적, 탈출 판정, 30분 플레이 분량의 목표 설계는 아직 구현하지 않았습니다. 원격 저장소나 운영 사이트에 게시하지 않았습니다.

## 일반 하역장 디자인 개선

- 선로 곡선과 경사를 먼저 결정한 뒤 15m의 기본 여유를 두고 양쪽 작업장을 계획합니다. 중앙 조망 구간에서는 양쪽 벽이 동시에 시야에 들어오며, 첫 구역은 상승 조망 코스입니다.
- 데크 하부 기둥과 가새, 창고 반입구, 선로 접근 계단, 하부 유지보수 갤러리와 공용 배관을 연결했습니다. 설비 디테일은 가까운 작업장에 집중했습니다.
- 컨베이어는 상·하부 벨트, 끝단 드럼, 롤러, 구동 모터와 지지 다리가 있습니다. 갠트리 크레인은 주행 레일·거더·트롤리·권상 드럼·와이어·후크가 구분됩니다. 탱크에는 펌프·배관·플랜지·밸브·점검 사다리를 붙였습니다.
- 작업등 아래 바닥은 정점 색으로 빛 번짐을 표현합니다. 가까운 조명만 기존 4개 광원 풀을 재사용합니다. 멀리 보이는 설비와 하부 기둥은 기존 높이 기반 안개에 잠깁니다.
- 일반 구역 생성은 배경·개별 작업장·횡단 구조·선로·최종 메시 단계로 분할했습니다. 정적 설비는 배치하고, 컨베이어 화물만 매 프레임 갱신합니다.
- 추가 검사: 4개 시드의 48개 코스, 33,648개 경사 표본, 양쪽 작업장과 접근 계단, 좌우 반전 모따기 면 방향, 분할 생성과 일괄 생성의 일치, 장시간 화물 좌표 유효성. 검사 표본 최대 경사는 약 17.5%입니다.
- 빠른 비교: ?seed=1234&s=625&ext&orbitYaw=-0.8&orbitPitch=0.18&orbitZoom=1.7&stop (중앙 고가 조망), ?seed=1234&s=245&yaw=-2.8&pitch=0.08&stop (펌프·탱크 작업장). 서버 주소 뒤에 ?부터 붙입니다.
- 이번 로컬 브라우저 검사에서는 정지 조망과 짧은 주행을 확인했습니다. 장시간 프레임 지연, 저사양 GPU, 실제 인터넷 4인 플레이의 성능 보증은 포함하지 않습니다. 추가 계단과 작업장 바닥은 현재 시각 구조이며 하차용 충돌 지형은 아직 아닙니다.
