# Voidrail 넷코드 설계

목표는 하나다. **다른 승객의 움직임이 끊기거나 순간이동하지 않는 것.**
그래서 서버 권한, 치트 방지, 대규모 접속보다 '부드러운 재생'에 모든 선택을 맞췄다.

## 스택

| 계층 | 선택 | 이유 |
|---|---|---|
| 연결 | **WebRTC P2P** ([Trystero](https://github.com/dmotz/trystero)) | 서버 운영 없이 GitHub Pages 만으로 배포. 데이터가 브라우저끼리 직접 오가서 중계 서버를 거치는 것보다 지연이 짧다 |
| 신호 교환 | 공용 Nostr 릴레이 (기본) / 자체 `ws-relay` (선택) | 처음 서로를 찾을 때만 쓰고, 연결 후에는 관여하지 않는다 |
| 위치 채널 | **비신뢰·비순서 데이터채널** (`ordered:false, maxRetransmits:0`) | TCP·WebSocket 은 패킷 하나가 늦으면 뒤 패킷까지 줄줄이 멈춘다(head-of-line blocking). 위치는 최신 값만 중요하니 늦은 건 버리는 게 맞다 |
| 이벤트 채널 | 신뢰·순서 채널 (Trystero 기본) | 레버·자원 줍기·시계 동기화처럼 빠지면 안 되는 것 |
| 렌더링 | three.js r160 (저장소에 포함) | CDN 장애와 무관하게 동작 |

## 끊김 없는 재생의 4단계 (`js/net/interp.js`)

1. **지연 재생 버퍼**
   '지금'이 아니라 `지연 시간`만큼 과거를 재생한다. 그러면 거의 항상 앞뒤 스냅샷 두 개 사이를 보간하게 된다. 패킷이 들쭉날쭉 도착해도 화면 속 움직임은 일정하다.
2. **3차 Hermite 보간**
   위치와 속도를 함께 맞춰 이어붙인다. 방향을 바꿔도 꺾이지 않고 곡선으로 움직인다.
3. **적응형 지연**
   지연 = 편도 전송 시간 + 전송 간격 × 1.3 + 지터 × 2.5. 네트워크 상태에 따라 자동으로 늘거나 준다. 바꿀 때는 재생 속도를 ±8% 범위에서만 조절해서 시간이 '점프'하지 않는다.
4. **외삽 + 오차 감쇠**
   패킷이 끊기면 마지막 속도로 최대 0.25초까지 예측해서 움직인다. 새 패킷이 와서 예측이 틀린 걸 알게 돼도 즉시 고치지 않는다. 차이를 약 0.1초에 걸쳐 녹여서 순간이동을 막는다.

## 좌표: 기차 통합 좌표

기차는 시속 수십 km로 달리고 커브를 돈다. 월드 좌표를 보내면 기차 위치가 미세하게 어긋나기만 해도 아바타가 떨린다. 그래서 위치를 **기차 기준 좌표**로 보낸다.

여러 차량의 로컬 좌표를 `x - 차량오프셋`으로 펴서 하나의 직선 좌표로 만들었다. 덕분에 차량 사이를 건너갈 때도 값이 연속적이다.

## 시계 동기화 (`js/net/clock.js`)

상대마다 ping/pong 으로 왕복 시간을 잰다. 최근 12개 표본 중 RTT 가 가장 짧은 4개의 평균으로 시계 차이를 추정한다(짧을수록 대칭에 가까워 정확함). 추정값이 바뀌어도 25%씩 천천히 따라가서 재생 시계가 튀지 않는다.

## 스냅샷 (`js/net/snapshot.js`)

20Hz, 44바이트 바이너리다. 구성: 순번, 보낸 시각(f64), 위치·속도(f32×6), 시선(yaw/pitch), 상태 플래그(땅/중력/달리기).

보내는 속도는 '게임 시간'이 아닌 '실제 시간' 기준으로 보정한다. 프레임이 느린 기기에서도 상대 화면의 외삽이 정확하도록 하기 위해서다.

## 기관사(호스트)

ID 가 가장 작은 참가자가 기관사가 된다. 기관사가 나가면 다음 사람에게 자동으로 넘어간다.
- 기관사는 기차 위치, 속도, 시각, 시드를 4Hz 로 방송한다.
- 나머지는 '방송 시점 + 경과 시간 × 속도'로 예측한다. 작은 오차는 부드럽게 보정하고, 250m 이상 어긋나면 로딩 화면을 거쳐 재배치한다.
- 레버(속도 조절)는 누구나 쓸 수 있다. 시드 변경과 지역 이동은 기관사만 할 수 있다.

## 자원 동기화

자원의 위치와 ID(`청크:번호`)는 시드에서 결정론적으로 정해진다. 품질 설정과 무관하게 모두에게 같다. 누가 주우면 ID 만 방송하고, 늦게 들어온 사람은 기관사에게 이미 주운 목록을 받는다.

## 측정 결과 (로컬 시뮬레이션, 원을 그리며 걷기 + 주기적 점프, 20초)

| 조건 | 방식 | 평균 오차 | 최대 오차 | 튐 | 멈칫 |
|---|---|---|---|---|---|
| 지연 80ms · 지터 40ms · 손실 5% | 보간 재생 | 4.6cm | 17cm | 0 | 8 |
| | 단순 최신값 | 51cm | 107cm | 306 | 822 |
| 지연 150ms · 지터 60ms · 손실 10% | 보간 재생 | 0.8cm | 8cm | 0 | 14 |
| | 단순 최신값 | 66cm | 137cm | 214 | 869 |

오차는 '재생 지연만큼 과거의 실제 위치'와 화면 위치의 차이다. 멈칫은 대부분 접속 직후 버퍼가 차기 전의 프레임이다.

## 테스트 방법

```
# 같은 브라우저 두 탭에서, 인위적인 지연·지터·손실로
http://localhost:8000/?net=local&lag=120&jitter=40&loss=0.05&room=TEST
# 디버그 패널(FPS·RTT·재생지연·외삽 비율)
http://localhost:8000/?room=TEST#debug
# 자체 신호 서버로 실제 WebRTC 경로 테스트
npm run relay   →   http://localhost:8000/?signal=ws://localhost:8787&room=TEST
```

## 알려진 한계

- **NAT 환경:** 일부 회사·학교망, 모바일망(대칭형 NAT)에서는 P2P 직접 연결이 안 될 수 있다. 이때는 TURN 서버가 필요하다. `js/net/transport.js` 의 `turnConfig` 에 넣으면 된다.
- **인원:** 모두가 서로 직접 연결하는 메시 구조라 8명 정도가 현실적인 상한이다.
- **보안:** 서버 권한이 없으니 조작된 클라이언트를 막을 수 없다. 친구끼리 협동 플레이를 전제로 한다.
